# Reflection

 ## *1. What was learnt*
AI has been a very useful tool in a few specific areas: quick fixes, inproving the visual side of the website, refactoring existing code and suggesting enhancements I hadn't thought of.

The biggest impact was on CSS. 

After constantly adding new features, the file became messy and hard to edit. 
Asking th AI to reorganize it saved me a lot of time and made it easier to maintain.
It also helped a lot with the undertanding of CSS patterns I hdn't used before, like custom properties, transitions which made the finishing result more apealing and profesional.

On the other side, for JavaScript, AI was helpful for speeding up implementations I already understood conceptually. 
I could pose the logic and afterwards use the ai to fill in details faster and help me look for redundancies and upgrades for the code in the more developed stage.

 ## *2. What can be improved*


The main issue was prompting. Early on I often had to ask twice for the same thing because my first prompt was too vague or missing context. I learned that giving the AI the relevant code snippet, the exact behaviour I wanted, and what was going wrong made a big difference in the quality of the response.

I also noticed that different tools have different strengths. 

ChatGPT excelled at debugging and finding and fixing logic errors, but struggled with CSS, the suggestions didn't work as tintended and more often than not it didn't apply the wanted change. 
Claude handled CSS, HTML and JS more consistently, but ChatGPT felt more direct when I had a specific bug to isolate.

The other failure mode was blind copy-pasting. I applied AI-generated code without reading it first a few times for CSS and sometimes worked and then i checked the diferences, and somo other time intruduced new problems, in those cases I simply read through the code and aplyed changes little by little to fix the especific problem.

 ## *3. Risks*
The biggest risk is using code you don't understand. It works until it doesn't, and when something breaks you have no idea where to start. That's a bad position to be in.
There's also the risk of skipping the thinking step entirely, going straight to AI instead of trying to reason through the problem first. 
That usually is faster on short-term, but you work with something you don't understant fully why it works.
FInally, over-using AI on the long run makes you not learn essential skills as debugging or logic solving.

 ## *5. When use AI*
- When I know what I want to do but not how to specificlty implement it with CSS or JS
- When I have a new error that I don't know how to solve, anfter trying, ask the AI
- When after working with the code makes it disorganized and hard to read, asking the AI to reorganize it saves a lot of time
- When I need new and fresh ideas or alternatives to existing code or structure

 ## *6. When NOT use AI*
- When I'm learning something, try first manually and check other sources
- When desingning the structure and main logic, if not it will be more difficult to maintain something I didn't make
- For debbuging, learn my way and have practice with error so I understand why it didn't work.
